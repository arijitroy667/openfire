# Codex agent evaluation results — 2026-10-26

## Run design

The 72-session experiment completed with 12 isolated fixtures, three repetitions per fixture, and two conditions. Each session used Codex `gpt-6-luna` at low reasoning effort, the same prompt, workspace-write auto-review, a 30-tool-call cap, and a 15-minute timeout. The control had no EngBrain server; the memory condition had a local MCP server seeded with 12 target episodes and 30 distractors. Final verification used the original tests in a fresh directory.

With the user's approval, one free Codex reset was used to cover the experiment. No paid credits were used.

The five public-issue fixtures are simplified, dependency-free reproductions based on [Requests #6071](https://github.com/psf/requests/issues/6071), [Requests #4673](https://github.com/psf/requests/issues/4673), [pytest #12659](https://github.com/pytest-dev/pytest/issues/12659), [Click #1884](https://github.com/pallets/click/issues/1884), and [Click #3059](https://github.com/pallets/click/issues/3059). They do not reproduce the full upstream repositories. The other seven fixtures are synthetic.

## Results

| Development | Control | 12 | 11 | 91.7% | 6 |
| Development | EngBrain memory | 12 | 12 | 100% | 7 |
| Held-out test | Control | 24 | 23 | 95.8% | 5 |
| Held-out test | EngBrain memory | 24 | 24 | 100% | 7 |
| Public issue fixtures | Control | 15 | 14 | 93.3% | 6 |
| Public issue fixtures | EngBrain memory | 15 | 15 | 100% | 7 |
| Synthetic fixtures | Control | 21 | 20 | 95.2% | 5 |
| Synthetic fixtures | EngBrain memory | 21 | 21 | 100% | 7 |
| All fixtures | Control | 36 | 34 | 94.4% | 5 |
| All fixtures | EngBrain memory | 36 | 36 | 100% | 7 |

The two control failures were pytest #12659 repetition two and the synthetic CORS preflight fixture repetition three. Their matching memory runs passed. Both agents reported that tests passed without running a successful post-fix verifier; the independent verifier caught the failures.

Across 36 matched pairs, memory used fewer calls to pass in 3 pairs, control used fewer in 28, and 5 tied. The median was 7 calls with memory and 5 without. Thus the observed success difference did not come with fewer tool calls.

The median number of repeat failed verifier runs after the initial baseline failure was zero in both conditions. This metric is only a transcript proxy; it does not classify whether an attempted edit matched a ground-truth failed approach.

## EngBrain usage and integrity

- Codex called `search_episodes` in 33 of 36 memory sessions; three sessions solved the fixture without searching.
- In all 33 searches, the correct target episode was returned at rank one. Codex then called `get_episode` in each of those sessions.
- One `get_episode` call hit an automatic approval-review deadline. The session still passed independent verification using the returned search summary.
- No control session called an MCP tool. No session exceeded the tool cap or the 15-minute timeout, and no session modified a test file.
- The full EngBrain suite passed: **29 passed**.

## Interpretation and limits

On this small fixture set, the memory condition had two more successful final verifications, and every target episode was top-ranked when a search happened. Memory did not reduce tool calls; its median was two calls higher. Only two matched pairs had different pass outcomes, so this result is exploratory, not a reliable estimate of general effectiveness.

These were Codex sessions, not Claude Code sessions. The experiment validates the MCP treatment with Codex and does not directly measure Claude Code hooks. The five public cases are small reproductions, there are only three repetitions per case and condition, and the single model was configured at low reasoning effort. The repeat-attempt metric is weaker than the PRD's ground-truth classification. A larger follow-up should use full upstream tasks, more incidents and models, and adjudicated transcript labels before making product-effectiveness claims.
