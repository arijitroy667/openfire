The problem

A debugging session creates the knowledge you need six weeks later — and almost none of it survives.

Transcripts are not the answer. They are huge, noisy, full of secrets, and they carry no notion of whether the advice still matches the repository.

01 — repetition

Failed attempts get repeated

An agent tries the approach you already ruled out, because nothing recorded that it failed and why.

02 — context loss

Reasoning lives in a chat

The workaround works, but the constraint that forced it is gone the moment the session scrolls away.

03 — rot

Notes outlive their truth

"Raise the connection pool" was right six months ago. The pool was rewritten twice since, and nothing says so.

04 — proof

Opinions look like evidence

Without provenance you cannot separate an observed pass from a confident guess written in a markdown file.

How it works

Capture, review, recall. Nothing skips the human gate.

Claude Code hooks record what the shell actually returned. Two or more failures followed by a passing run become a draft — never a searchable memory.

01

Capture the shell

Asynchronous PostToolUse and PostToolUseFailure hooks store the redacted command, the exit code, and the last 2 KB of output.

events expire after 7 days
secrets scrubbed before storage
02

Detect the recovery

Two failures of the same normalized command, then an exit code of 0, produce a draft with attempts, a diff summary, and the passing commit.

session-scoped · deduplicated
never claims which edit fixed it
03

Review it as a human

engbrain review lists drafts. Edit the narrative, then accept or reject. Only acceptance moves a record into search.

mechanical evidence → verified
everything else stays unverified
04

Recall before the edit

A synchronous PreToolUse hook searches the file's path anchors and injects up to three matching episodes with freshness reasons.

3 s budget · fails open
skips .env, keys, certificates
05

Re-rank with evidence

FTS5 text, exact error signatures, and path anchors are fused with reciprocal-rank fusion, then nudged by evidence grade and staleness.

RRF k=60 · max 5 results
superseded records never appear
Architecture

One engine, three front doors, one local database.

The CLI, the stdio MCP server, and the hook adapter are thin layers over the same Python engine. Everything is scoped to the repository the process started in.

Evidence, not vibes

Every record says how it was proven and how old it is.

An anchor is a file, a dependency version, or a commit. Staleness is recomputed from Git and your manifests on every read — never from a timestamp someone typed.

Evidence grades

human accepted
mechanical

Observed command outcomes. Becomes verified only after a person accepts it.

asserted

Written by an agent with supporting text. Never upgrades itself.

none

Hand-written notes. Accepted immediately, permanently unverified.

A fail-then-pass sequence is evidence that the outcome changed — not proof of which edit caused it.
