Documentation

Everything EngBrain does, and how to wire it up.

EngBrain is a local-first, repository-scoped engineering memory for AI coding agents. It records the commands that failed, the attempts that did not work, and the evidence that a fix passed — then serves accepted episodes over MCP with Git-computed freshness.

Overview

Four moving parts, one Python package:

  • CLI — engbrain init, review, recall, eval, and the rest.
  • Hook adapter — captures Claude Code Bash and PowerShell outcomes and injects context before Edit and Write.
  • MCP server — three tools over stdio: search_episodes, get_episode, propose_episode.
  • SQLite + Git — episodes, anchors, and FTS5 live in .engbrain/engbrain.db; freshness is read from Git and your dependency manifests.
Two rules govern everything: drafts and rejected records are never searchable, and retrieved text is historical context that EngBrain never executes.

Requirements

RequirementNotes
Python 3.11+CI covers 3.11 and 3.12 on Linux and Windows.
Git CLIRepository discovery, anchors, staleness.
SQLite with FTS5Required for search. engbrain doctor reports whether your interpreter has it.
uv or pipxInstalling and running the project.

Runtime dependencies are typer, pydantic v2, tomlkit, and the MCP Python SDK. The llm extra adds openai; the dev extra adds pytest.

Install

Install once from the EngBrain checkout. You do not install it into the repository you want it to remember.

git clone https://github.com/arijitroy667/openfire.git
pipx install --editable .\openfire

For development, use uv instead:

cd openfire
uv sync --extra dev
uv run engbrain --version
The generated client configurations launch the bare engbrain command. If you only ever run uv run engbrain ..., the agent's process will not find it and engbrain doctor will report “configured but engbrain is missing from PATH”.

Quick start

From the root of the Git repository you want EngBrain to remember:

cd C:\work\my-project
engbrain init --client claude-code
engbrain doctor
engbrain status

init creates .engbrain/engbrain.db, adds /.engbrain/ to the clone's .git/info/exclude, and writes the selected client's configuration. Run engbrain doctor after any client change.

Initialize a repository

The init command takes two options:

OptionPurpose
--name NAMEOverride the project name, which defaults to the repository folder name.
--client none|claude-code|codex|cursor|vscodeWrite project-level configuration for one client. Defaults to none.

Run init --client ... again for other clients: files are merged, not overwritten. A conflicting engbrain entry that belongs to a different command is reported instead of being clobbered.

Connect Claude Code

engbrain init --client claude-code

This writes two files:

  • .mcp.json registers a stdio server named engbrain with args: ["mcp", "serve", "--root", "${CLAUDE_PROJECT_DIR:-.}"].
  • .claude/settings.local.json gains three hook entries, merged into any hooks you already have.
EventMatcherModeTimeoutEffect
PostToolUseBash, PowerShellasync10 sRecords a successful command event
PostToolUseFailureBash, PowerShellasync10 sRecords a failed command event
PreToolUseEdit, Writesync3 sInjects up to 3 anchored episodes, then lets the edit proceed

The pre-edit hook returns hookSpecificOutput.additionalContext capped at 7,000 characters. It fails open: if the repository is not initialized, the file is .env or a key/certificate, or nothing matches, it returns no context and the edit happens unchanged.

Capture contract

Every event stores the redacted command, the exit code, the last 2 KB of output, the working directory, and the commit at capture time. Events are deleted seven days after they are written.

Restart Claude Code after the first init so the MCP server is spawned and project hooks are loaded.

Connect Codex

engbrain init --client codex

Adds a project entry to .codex/config.toml, preserving existing formatting:

[mcp_servers.engbrain]
command = "engbrain"
args = ["mcp", "serve", "--root", "."]
cwd = "."

Codex loads project-level configuration for trusted projects, so approve the directory once. Codex has no EngBrain hooks: it can search and propose episodes, but nothing is captured automatically.

Connect Cursor

engbrain init --client cursor

Writes .cursor/mcp.json:

{
  "mcpServers": {
    "engbrain": {
      "type": "stdio",
      "command": "engbrain",
      "args": ["mcp", "serve", "--root", "${workspaceFolder}"]
    }
  }
}

Restart or reload Cursor, then approve the server when prompted.

Connect VS Code

engbrain init --client vscode

Writes .vscode/mcp.json, which uses servers rather than mcpServers:

{
  "servers": {
    "engbrain": {
      "type": "stdio",
      "command": "engbrain",
      "args": ["mcp", "serve", "--root", "${workspaceFolder}"]
    }
  }
}

Connect any other MCP client

Any client that can launch a stdio server works. Register this entry:

{
  "mcpServers": {
    "engbrain": {
      "type": "stdio",
      "command": "engbrain",
      "args": ["mcp", "serve", "--root", "C:/work/my-project"]
    }
  }
}

Use an absolute path when the client does not expand workspace variables. To check the server by hand, run engbrain mcp serve --root . inside the repository: it speaks JSON-RPC over stdio and prints nothing else.

MCP tools

Three tools, all scoped to the repository the server started in. Search and lookup results carry "untrusted": true.

ToolParametersReturns
search_episodes queries (1–5), paths, episode_type, limit (max 5) Ranked summaries with status, evidence kind, staleness, reasons, anchors, and match_reason
get_episode episode_id Full episode, anchors, staleness level and reasons, provenance
propose_episode title, episode_type, problem, context, attempts, solution, evidence_text, paths The new draft's id, review_state, status
  • search_episodes searches accepted episodes only.
  • propose_episode creates a draft with origin=agent that a human must accept.
  • Event output tails are never returned over MCP, only stored locally.

A full session

engbrain init --client claude-code

# review what the hooks captured
engbrain review
engbrain review edit EPISODE_ID --solution "Raised the pool limit to 4" --verification "check_pool.py passes"
engbrain review accept EPISODE_ID

# search it later with more than one phrasing
engbrain recall --query "connection pool exhausted" --query "workers cannot get a connection" --path src/pool.py

# record whether the result was useful
engbrain feedback EPISODE_ID helpful

Episode lifecycle

StateMeaning
draftCreated by a hook sequence, an agent proposal, or an LLM draft. Never searchable.
accepted + verifiedHuman accepted a record whose stored evidence contains an exit code of 0.
accepted + unverifiedHuman accepted a record without mechanical evidence. Searchable, but labelled.
rejectedReviewer declined it. Kept locally, never searchable.
supersededReplaced by a newer accepted episode. Inspectable, excluded from search.

Anchors

  • path — changed or untracked files since the first failure's commit (max 50, sensitive paths skipped).
  • dependency — names found in the command or error text, resolved through the local manifest snapshot.
  • commit — the commit at the passing run.

Recognized manifests: uv.lock, poetry.lock, Pipfile.lock, requirements*.txt, and pinned entries in pyproject.toml.

Evidence & staleness

Evidence grades are mechanical (observed command outcomes), asserted (an agent supplied supporting text), or none. Only mechanical evidence can become verified, and only after a person accepts it.

LevelMeaning
freshAnchors exist and Git reports no changes touching them.
driftedWorking-tree changes, 1–19 commits touching anchors, or a same-major dependency change.
staleAn anchored path was deleted or renamed, 20+ commits touched anchors, a dependency was removed, or a major version changed.
unknownAnchors are missing, or Git history, a capture commit, a pinned version, or a working-tree read is unavailable.

Ranking fuses three candidate lists with reciprocal-rank fusion (k = 60): FTS5 bm25, exact normalized error signature, and path anchor equality. Small adjustments then apply: +0.002 signature, +0.001 path, -0.0005 unverified, and small penalties as staleness worsens.

Demo repository

examples/demo-repo reproduces three deterministic incidents, each with a failing check, a one-line fix, and an anchor to watch.

python scripts/check_pool.py          # connection pool exhaustion
python scripts/check_dependency.py    # dependency pin mismatch
python scripts/check_runtime_flag.py  # empty environment-variable value

python scripts/offline_demo.py capture all
python scripts/offline_demo.py drift pool

Run each check twice so the hooks see failures, apply the fix, then run it once more. The step-by-step recording plan is in examples/demo-repo/VIDEO_DEMO.md.

Troubleshooting

“EngBrain is not initialized here”

Run engbrain init from inside the target repository. EngBrain resolves the Git root first; a folder without a repository cannot be initialized.

“configured but engbrain is missing from PATH”

The client configuration launches the bare engbrain command. Install it with pipx install --editable .\openfire or activate the virtual environment before starting the agent.

SQLite FTS5 check fails

Your interpreter's SQLite was built without FTS5. Use a python.org build, or a distribution package of libsqlite3 compiled with --enable-fts5.

Nothing appears in search after a fix

The detector needs two failures of the same normalized command in one session, followed by an exit-code-0 run. Drafts also stay invisible until engbrain review accept.

The pre-edit hook injects nothing

That is the fail-open path: repository not initialized, file is .env/key/certificate, no accepted episode matches the path, or the 3-second budget expired.

Limits & license

  • Redaction is best-effort and is not a security boundary.
  • Hook capture supports documented Claude Code Bash and PowerShell payloads and never blocks a tool call.
  • Only Claude Code gets automatic capture and pre-edit recall.
  • A fail-then-pass sequence does not attribute the pass to a specific edit.
  • Retrieval is lexical, with error signatures and anchors; embeddings are deliberately absent.
  • Data is local and project-scoped: no team sync, dashboard, or remote database.
